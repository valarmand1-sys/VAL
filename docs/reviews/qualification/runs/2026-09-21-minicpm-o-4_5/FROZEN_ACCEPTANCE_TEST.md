# MiniCPM-o 4.5 — the frozen acceptance test

**Owner implementation order, 21 September 2026.** One bounded acceptance test,
three modality cases, run once. The candidate passes only if **all three** pass.
If it fails, the exact failed criterion is reported and the work stops.

**This file is committed before any inference is run**, so the record shows the
criteria preceded the results. Nothing below may be added to, softened, or
re-run with different prompts after seeing an answer. A genuine installation or
integration defect that stopped the model from receiving the intended input at
all may be corrected; the model may not be tuned against the answers.

Candidate role: **Val local perception provider** — grounded observations from
images, audio and video. Not final cognition. Val Core remains Val; GPT-OSS
remains the cognition provider; MiniCPM-o is a replaceable perception provider
owning no identity, memory, policy or conversation state.

## Case A — image perception

**Fixture.** The genuine attachment from the Track C image turn, read from the
governed attachment store rather than from a copy.

- attachment id `01a0c109-8993-7842-b309-73b169e4a27c`
- original SHA-256 `7fc13a7c5072b69acc119d20a16beb6523dc21aa4ba6a4ef950c7ba748c12db0`

**Prompt, exactly:**

```
Report only what you can actually see in this image. Do not guess, do not
interpret motives, and do not add anything that is not visible. Cover: how many
people are present; what the child is wearing; what the people are doing; the
setting; and any major visible continuity details.
```

**Passes only if all four central facts are established:**

1. three people are present;
2. the child/boy is dressed as a magician, including the top hat;
3. the people are embracing/hugging;
4. they are indoors, in a living-room or home environment.

Additional accurate detail is welcome. Exact wording is not required.

**Fails if it** materially miscounts the people, misses the magician
identity/costume, materially misstates the central action, materially misstates
the setting, or invents a central person, object or action that is not present.

## Case B — audio perception

**Fixture.** One deterministic local recording, generated by
`make_audio_fixture.sh` using the Mac's own speech synthesis. No cloud service.
20–30 seconds, clean single speaker, English. The frozen semantic content:

```
The lantern is beside the blue book.
The number is forty-two.
After breakfast, Mara will meet Daniel at the old stone bridge.
She should bring the red envelope, not the green one.
```

**Prompt, exactly:**

```
Report the substantive content of this recording. State the information it
conveys. Do not add anything that was not said.
```

**Passes only if the result preserves every one of these:**

1. the lantern is beside the blue book;
2. the number is forty-two;
3. the meeting happens after breakfast;
4. Mara meets Daniel;
5. the location is the old stone bridge;
6. the red envelope is the one to bring;
7. the green envelope is explicitly *not* the one to bring.

Punctuation and non-substantive wording differences do not matter.

**Fails if it** materially invents, omits, reverses or changes any of those.

**Scope of a pass, stated in advance.** It establishes that the local audio path
delivers audio to the model and that MiniCPM-o recovers substantive content from
clean single-speaker speech. It establishes **nothing** about overlapping
speakers, music under dialogue, noisy production audio, speaker identification,
or emotional and tonal judgment. Those are not tested and must not be claimed.

## Case C — video perception

**Fixture.** One deterministic short local video, generated by
`make_video_fixture.py`. No cloud generation service. Roughly 6–10 seconds,
carrying one unmistakable ordered sequence and **no explanatory text**:

1. a red square appears on the **left** of the frame;
2. it moves to the **centre**;
3. it moves to the **right**;
4. a blue circle then appears **beneath** it.

**Prompt, exactly:**

```
Describe what happens in this video and the order in which it happens. Report
only what is visible.
```

**Passes only if the result establishes:**

1. the red square begins on the left;
2. it moves through the centre;
3. it ends on the right;
4. the blue circle appears after that movement;
5. the circle is beneath the square.

**Fails if it** materially reverses the sequence, loses the cross-frame
movement, or invents a different central event.

How the runtime actually presents the video to the model — sampling rate, number
of frames delivered, any frame-selection behaviour — is recorded as observed.

## Whole-test requirements

Beyond the three cases individually, the qualification passes only if:

- all perception inference occurs locally;
- no OpenAI, Anthropic, Google or other cloud cognition or perception call
  occurs during it;
- provider inference cost is $0;
- the exact model, runtime and artifact identity is recorded;
- there is no silent fallback;
- the runtime does not crash;
- each result is unambiguously associated with its source media;
- the perception result can be handed back to Core as grounded information
  rather than treated as Val's final response.

Latency is recorded per modality as an operational measurement. It is not a
pass/fail criterion unless the runtime fails to complete or is operationally
unusable.
